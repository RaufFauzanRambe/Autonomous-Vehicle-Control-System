# sample_data/camera — Synthetic front-camera dataset

Four 640x480 JPG frames (10 fps stream, first 4 frames of the scenario)
from a simulated front camera, plus pinhole calibration and 2-D bounding
box annotations. The scene is generated by projecting 3-D box models of
the scenario's static obstacles (lead vehicle at 30 m left offset 3 m,
sign pole at 25 m left 6 m, barrier at 55 m right 2 m) with the shipped
calibration, so image content, annotations and calibration are mutually
consistent by construction.

## Files

| File | Content |
|---|---|
| `camera_metadata.json` | Device, resolution, fps, mount pose, per-frame list with timestamps [s] |
| `camera_calibration.json` | Intrinsics (fx = fy = 320 px, cx = 320, cy = 240), distortion, extrinsics, projection model |
| `images/frame_00000{1..4}.jpg` | Frames at t = 0.0, 0.1, 0.2, 0.3 s (JPEG quality 90) |
| `annotations/frame_00000{1..3}.json` | Bounding boxes `[x_min, y_min, x_max, y_max]` [px], origin top-left, classes: `car`, `traffic_sign`, `barrier` |

## Projection model

```
u = cx - fx * (Y / X)          # left offset Y appears LEFT in the image
v = cy + fy * ((h_cam - Z) / X)
X = forward distance [m], Y = left offset [m], Z = height [m], h_cam = 1.5 m
```

## Known gap

`frame_000004` is deliberately unannotated (`annotations/available_for`
in the metadata documents this). Keep it in mind when writing loaders:
annotation coverage is a data property, not an error.

## Extension points

Replace the synthetic frames with real recordings and keep the
annotation schema; re-run `tests/test_camera_sensor.py` to validate any
new batch (the tests only assume the documented structure, not the
synthetic content).
